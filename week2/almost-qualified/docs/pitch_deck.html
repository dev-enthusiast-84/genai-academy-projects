02 / The solution & the project one-liner

A clear claim. A bounded corpus.
An answer you can inspect.

My RAG app helps career changers answer which job requirements their documented experience supports and what evidence is missing, from one resume, two project artifacts, and three saved job descriptions, in a Streamlit evidence workspace, targeting 95% faithfulness and 80% retrieval precision@5.

For whom

Career changers

Translate existing work into evidence for a new role.

From what

Six demo documents

Streamlit workspace

04 / Architecture & model mapping

One evidence agent.
One selected model.

01 / Python · no LLM

Parse & chunk

Extract job requirements from Markdown. Split candidate documents into sections with source IDs.

02 / Python · no LLM

Retrieve with BM25

LocalRetriever ranks candidate evidence: up to five chunks per requirement. No embedding model.

03 / LLM used here

EvidenceAgent

Default: GPT-4 Turbo via LiteLLM. One assessment call covers the selected requirements and retrieved excerpts.

04 / Python · no LLM

Validate & display

Check status labels, citation IDs, candidate sources, and excerpt membership. Render and export results.

05 / Why this approach

Make the next career move
with evidence in hand.

RAG makes claims inspectable

Retrieve from the candidate’s own documents, then show the excerpts behind each assessment. Missing evidence becomes a specific action to take.

BM25 fits a focused MVP

Local keyword ranking is easy to inspect and needs no embedding service. It suits a small corpus with named tools; paraphrases remain a limitation.

A simple workflow is easy to try

Streamlit brings selection, review, and export into one place. LiteLLM supports provider choice; local mode enables a demo without model credentials.
