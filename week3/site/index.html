Consent has an undo button.

Recall helps fitness-club members withdraw questionnaire consent and linked copies in a browser dashboard, replacing repeated searches and removal checks across three apps; its investigator chooses three read tools, application code executes approved removal and verification, and it asks for human review when scope is unclear and before deletion, targeting verified removal with the booking preserved in under three minutes in 9 of 10 completable controlled trials. This target is not a measured result.

Goal
Withdraw a fitness questionnaire’s sharing consent and linked records while preserving the paid booking.
Surface
A browser privacy dashboard.
Steps
Consent → automatic sharing → source-only deletion → investigate → approve withdrawal → remove → verify.
Tools
Discover, trace, inspect, and verify are reads. Approved deletion is a write.
Memory
Conversation and API key stay in memory. Request progress persists in this browser for 24 hours; lineage and withdrawal markers remain until reset.
Hard limits
No unapproved deletion, cross-user access, guessed lineage, or false completion. Shared dependencies require review.
Human review
Approve exact targets and ingestion blocks. Changed scope needs a new plan; further attempts can be revoked.
Failure handling
Bounded retries, saved progress, and independent verification. An unavailable service stays unknown.
Success
Match expected end-to-end outcomes, preserve unrelated records, and report incomplete work honestly. Live-model success rates remain to be measured.

Club Portal, Class Booking, and Member Offers have separate pages and simulated service stores in this browser. Recall is the separate agent app. Search is lexical. Replay protection covers stable IDs through this demo's ingestion path; external systems, backups, and model weights are outside scope. Rehearsal is scripted and clearly labeled.
