Architecture / agent-to-model mapping

One evidence agent. One selected model.

The application separates job requirements from candidate proof. Python handles retrieval and validation; the selected LLM assesses the retrieved evidence.

01 / Python · no LLM

Parse & chunk

Extract job requirements. Chunk candidate documents by section, preserving IDs and line ranges.

02 / Python · no LLM

LocalRetriever

BM25 keyword search retrieves up to five candidate chunks per requirement. No embeddings or vector database.

03 / LLM assessment

EvidenceAgent

Default: GPT-4 Turbo via LiteLLM. One call assesses the selected requirements and returns structured JSON.

04 / Python · no LLM

Validate & display

Check labels, IDs, source category, and excerpt membership. Display in Streamlit and export Markdown.

Evidence boundary: job descriptions supply the questions. Only the resume and project artifacts enter the candidate evidence pool. Without a key, or with model assessment disabled, EvidenceAgent uses local Python rules.

The pitch / 5 slides · 2 minutes

See the whole story.

My RAG app helps career changers answer which job requirements their documented experience supports and what evidence is missing, from one resume, two project artifacts, and three saved job descriptions, in a Streamlit evidence workspace, targeting 95% faithfulness and 80% retrieval precision@5.

These are targets, not measured results. The current evaluator checks local labels, source coverage, and citation validity; it does not calculate these two metrics.

Deployment

Run the app. Publish the story.

Try locally

Install uv, then run from the repository root:

cd week2/almost-qualified
uv sync --python 3.14
uv run python ingest.py --corpus demo
uv run streamlit run app.py

Turn Use model assessment off to try without a key. For model mode, configure the chosen provider key in Streamlit secrets or the sidebar.

Deploy on Streamlit

  1. Push the app and dependency files to GitHub.
  2. Create a Community Cloud app for this repository and your deployment branch.
  3. Set the entrypoint to week2/almost-qualified/app.py.
  4. Select Python 3.14 in Advanced settings to match the current lockfile. Add provider secrets for model mode.
  5. Deploy; check supported, partial, and missing-evidence cases and Markdown export.

The lockfile requires Python 3.14+. Verify that version is offered before deployment.

Two separate surfaces: GitHub Pages hosts this static showcase and the deck. Streamlit hosts the Python application. After editing the showcase or deck, run python3 week2/almost-qualified/scripts/sync_showcase.py from the repository root, then publish the updated root docs/ folder.

Scope & approach

Useful evidence, with visible limits.

Local BM25 keeps this focused corpus easy to inspect. It can miss paraphrases; local assessment uses fixed rules. “No evidence found” describes the documents, not the candidate’s ability. The next step is evaluating grounding and retrieval before adding a more complex search pipeline.
