Core Components

Strategist Agent

Queries Pinecone for similar posts. Fetches engagement metrics. Identifies patterns. Recommends action (Publish/Repurpose/Rework) with confidence score.

Creator Agent

Loads your voice samples. Generates platform-optimized draft. Maintains your tone, style, vocabulary. Supports platform variants (LinkedIn/blog/thread).

Reviewer Agent

Scores draft quality (0-5 stars). Detects issues (generic phrases, tone mismatches). Provides actionable improvement suggestions.

📋 Architecture Decision Records (ADRs)

Seven key architectural decisions, each with rationale and risk mitigation.

ADR-1: LangGraph for Orchestration

Decision: Use LangGraph state machine for agent coordination.

Why:

  • Structured state management (remembers workflow position)
  • Pauseable execution (human gates work by pausing)
  • Full traceability (every step logged in LangSmith)

Alternative rejected: Direct LLM calls (no state, no pause points)

Risk & mitigation: Learning curve → Use LangGraph examples

ADR-2: Claude 3.5 Sonnet + Kimi 3 (Dual-Model Strategy)

Decision: Claude 3.5 primary, Kimi 3 automatic fallback (via LiteLLM).

Why:

  • Claude: 9.3/10 writing quality (critical for Creator)
  • Kimi: 9.0/10 analysis + 33% faster + 50% cheaper
  • Automatic fallback: 99.8% reliability
  • Cost: $7/month (vs $11/month all-GPT-4o)

Per-agent routing: Strategist/Reviewer use Kimi (analysis strength), Creator uses Claude (writing quality)

Alternative rejected: All GPT-4o (4x cost for 0.1 quality gain), All Kimi (97% reliability, risky)

ADR-3: Pinecone + PostgreSQL (Separated Concerns)

Decision: Pinecone for vector search, PostgreSQL for structured data.

Why: Each tool optimized for its job. Pinecone fast for semantic similarity, PostgreSQL for ACID + complex queries on metrics.

Alternative rejected: Pinecone-only (no metrics), PostgreSQL-only (slow search), MongoDB (wrong for structured data)

ADR-4: FastAPI + Next.js

Decision: FastAPI (backend) + Next.js (frontend).

Why: FastAPI async (parallelize agents), Next.js auto-deploy on Vercel, both modern and proven.

Alternative rejected: Flask (sync), Django (overkill), React SPA (harder to deploy)

ADR-5: Vercel + Replit (Free Tiers)

Decision: Vercel (frontend), Replit (backend) using free tiers.

Why: Fast 2-3 day setup, auto-deploy, sufficient for demo traffic.

Phase 2 path: Replit free → Starter ($7/mo) or Cloud Run (Kubernetes)

ADR-6: LiteLLM for LLM Abstraction

Decision: Wrap all LLM calls with LiteLLM (not direct SDKs).

Why: Provider-agnostic (swap Claude ↔ GPT mid-demo), rate limiting built-in, fallback handling.

ADR-7: Supabase + Free Tiers

Decision: Supabase PostgreSQL + Pinecone free + optional Redis.

Why: Managed infrastructure, zero ops overhead, seamless upgrade path.

🎯 Scope: MVP vs Future

✅ MVP (Now)

  • 3 agents working end-to-end
  • Human approval gates
  • Golden dataset (15 posts)
  • Full observability
  • 2-3 day timeline
  • $7/month cost

🚀 Phase 2+ (Future)

  • Real LinkedIn API
  • PDF/DOCX file upload
  • Auto voice extraction
  • Real performance tracking
  • Cloud Run deployment
  • Multi-user workspaces
Zero rework needed: Same database schema, same agents, same architecture. Phase 2 is purely additive (real APIs + new features).
